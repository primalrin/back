# Поиск по документам

Простой поисковик по текстам документов: FastAPI + PostgreSQL (asyncpg) + Elasticsearch, всё асинхронное и запускается в Docker.

## Запуск

Нужны Docker и Docker Compose v2.

```bash
docker compose up -d --build --wait
```

Команда завершается, когда API готов принимать запросы. При первом старте `posts.csv` загружается в Postgres, а индекс Elasticsearch строится из БД. Перезапуски данные не дублируют.

- API: http://localhost:8000
- Swagger UI: http://localhost:8000/docs
- OpenAPI-спецификация: [docs.json](docs.json)

Остановить и удалить данные: `docker compose down -v`.

## API

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/documents/search?query=<текст>` | Первые 20 найденных документов со всеми полями из БД, упорядоченные по `created_date` (сначала новые) |
| `DELETE` | `/documents/{id}` | Удаляет документ из БД и индекса: `204`, или `404`, если документа нет |

```bash
curl -G http://localhost:8000/documents/search --data-urlencode "query=конкурс"
curl -X DELETE http://localhost:8000/documents/2
```

```json
[
  {
    "id": 287,
    "rubrics": ["VK-1603736028819866", "VK-84114350314", "VK-13456892213"],
    "text": "...",
    "created_date": "2019-11-25T07:20:37"
  }
]
```

На Windows `curl` отправляет кириллицу в кодировке консоли, поэтому запросы на русском удобнее делать через Swagger UI.

## Тесты

Функциональные тесты ходят в API и работают с настоящими Postgres и Elasticsearch, но в отдельных БД и индексе (`documents_test`). Основные данные они не трогают.

```bash
docker compose run --rm api pytest
```

## Решения

- **Postgres хранит документы, Elasticsearch хранит только индекс** с полями `id` и `text`, как требует задание. Для `text` используется анализатор `russian`, поэтому «котики» находят «котиков».
- **Как работает поиск.** Elasticsearch возвращает 20 самых релевантных `id`, затем документы читаются из Postgres и сортируются по `created_date DESC`. Даты в индексе по условию нет, поэтому сортировка идёт в БД. Если упорядочить по дате все совпадения, получится не поиск, а фильтр по слову: на частых словах вверху окажутся просто свежие посты.
- **`id`.** В CSV идентификаторов нет, их выдаёт Postgres при импорте в порядке строк файла (1…1500).
- **Импорт** (`python -m app.loader`) запускается при старте контейнера. CSV загружается только в пустую таблицу. Индекс перестраивается из БД, если его нет или число документов в нём расходится с таблицей.
- **Удаление.** Строка удаляется из Postgres внутри транзакции, затем документ удаляется из Elasticsearch. Если Elasticsearch недоступен, транзакция откатывается, и БД с индексом не расходятся.
- **Сознательно не стал делать:** миграции (таблица одна, хватает `CREATE TABLE IF NOT EXISTS`), ORM, пагинацию и авторизацию. Задача их не требует.

## Структура

```
app/
  main.py         FastAPI-приложение и эндпоинты
  storage.py      схема БД, маппинг индекса, поиск и удаление
  loader.py       импорт CSV → Postgres → Elasticsearch
  config.py       настройки из переменных окружения
  export_docs.py  генерация docs.json
tests/            функциональные тесты
docs.json         OpenAPI-спецификация
```

`docs.json` генерируется из кода. Тест проверяет, что спецификация не устарела. Перегенерировать:

```bash
docker compose run --rm --no-deps -T api python -m app.export_docs > docs.json
```
